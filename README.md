# 好友门卫（astrbot_plugin_friend_gate）

让 AstrBot 能自己处理 QQ 的三种请求：**好友申请、被拉进群、别人申请进你的群。**
该通过的秒过，不该通过的直接拒，每一次都告诉你。

## 它解决什么问题

AstrBot 收到 OneBot 的 `request` 事件后，只把它当成一条空消息丢进消息管道，**不会替你调用 `set_friend_add_request` 或 `set_group_add_request`**。结果就是申请一直躺在 QQ 的「新的朋友」里，群邀请躺在「群通知」里，等你哪天想起来了手动点。

这个插件直接订阅协议端的 request 事件，把它变成一个确定的动作：

```
好友申请
  黑名单      → 直接拒绝
  白名单      → 直接同意（跳过暗号与频率限制）
  必须填验证语 → 没填就拒绝
  验证语暗号   → 不含关键词就拒绝
  每小时上限   → 超了不拒绝，只留给你人工看（避免误伤）
  以上都过    → 自动同意

入群邀请 / 加群申请
  总开关关    → 完全不动
  群黑名单    → 直接拒绝
  群白名单非空 → 只同意名单内的，其余留给你人工处理
  邀请附言暗号 → 不含关键词就拒绝
  每小时上限   → 超了留给你人工看
  以上都过    → 自动同意
```

全程**不经过大模型**，不吃 token，也不受模型限流影响。

## 功能

- 自动同意好友申请，可一键暂停（暂停期间申请原样留着，不会丢）
- 黑名单 / 白名单 / 验证语暗号 / 必须填验证语 / 每小时上限
- 同意后自动加备注（模板支持 `{nickname}` `{user_id}` `{comment}`）
- 处理结果私聊通知管理员
- 可选：同意后给对方发一句欢迎语
- **自动同意入群邀请**：有人把机器人拉进群，秒进
- **自动同意加群申请**：别人申请进机器人当管理员的群，秒过（独立开关，需要管理员权限）
- 群白名单 / 群黑名单 / 邀请附言暗号 / 群请求独立每小时上限
- 群请求通知带群号和群名，拒绝时可附理由
- 同一个申请只处理一次（跨插件重载也有效）
- 最近 50 条处理记录可查，好友申请与群邀请的规则都能试跑

## 安装

在 AstrBot WebUI 的插件页粘贴本仓库地址安装，或：

```bash
cd AstrBot/data/plugins
git clone https://github.com/xuanbaon/astrbot_plugin_friend_gate
```

然后重启核心，或在插件页点「重载」。无第三方依赖。

要求：AstrBot ≥ 4.17.0，平台适配器为 **aiocqhttp**（OneBot v11）。NapCat、Lagrange、SnowLuma 等协议端都走这条链路。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用好友门卫 | 开 | 总开关 |
| 处理结果通知管理员 | 开 | 私聊 `admins_id` 里的 QQ 号 |
| 通知目标会话（可选） | 空 | 填了就直接发到这个会话，优先级更高，形如 `snowluma:FriendMessage:123456` |
| 自动备注 | 空 | 模板，例如 `{nickname}-群友` |
| 同意后发欢迎语 | 空 | 留空不发 |
| 黑名单 QQ | 空 | 一律拒绝 |
| 白名单 QQ | 空 | 直接同意 |
| 验证语暗号 | 空 | 填了就要求验证语含其中一个词 |
| 必须填写验证语 | 关 | 验证语为空就拒绝 |
| 每小时最多自动通过 | 10 | 0 表示不限制 |
| 拒绝时回复的理由 | 空 | 协议端支持时才会带上 |
| **群请求** | | |
| 自动同意入群邀请 | 关 | 有人把机器人拉进群时自动同意 |
| 自动同意加群申请 | 关 | 别人申请进你管理的群时自动同意，需要机器人是群主/管理员 |
| 只同意这些群（群号） | 空 | 留空不限群；填了只同意名单内的，其余留给你人工处理 |
| 拒绝这些群（群号） | 空 | 一律拒绝，优先于白名单 |
| 邀请附言暗号 | 空 | 填了就要求附言含其中一个词 |
| 群请求每小时上限 | 5 | 与好友申请额度分开计算，0 不限制 |
| 拒绝入群时回复的理由 | 空 | 协议端支持时才会带上 |
| 群请求处理结果通知管理员 | 开 | 和好友申请共用通知目标会话 |

验证语暗号通常不建议开：多数人加好友时验证语是空的，开了会把人全拒掉。想拦陌生人，用白名单 + 黑名单更稳。

群请求也是同理：**先把「自动同意入群邀请」打开观察几天**，确认没有骚扰再考虑开「自动同意加群申请」。后者只有在机器人是群主或管理员时才有效。

## 命令

仅管理员可用：

```
/好友                      运行状态与累计统计
/好友 关                    暂停自动处理（申请先留着）
/好友 开                    恢复自动处理
/好友 记录                  最近处理过的申请（含群请求）
/好友 路径                  打印状态文件位置
/好友 测试 <QQ> [验证语]     只试跑好友申请规则，不会真的同意

/好友 群                    群请求的完整状态（开关、名单、累计）
/好友 群开 | 群关            开关「自动同意入群邀请」
/好友 加群开 | 加群关        开关「自动同意加群申请」
/好友 群白 123456           加群白名单（/好友 群白 -123456 删除，/好友 群白 空 清空）
/好友 群黑 123456           加群黑名单（同上）
/好友 群测试 123456 [附言]   只试跑群邀请规则
```

`群开/群关` 和 `群白/群黑` 走的是运行时状态，改完立刻生效，不用去面板改配置；面板里的静态名单依然有效，两边会合并去重。

## 兼容性说明

不同协议端对 `set_friend_add_request` 的参数支持不一样。有的一多传 `remark`（备注）或 `reason`（拒绝理由）就报参数错误 —— SnowLuma 就只认 `flag` + `approve`。

插件的处理方式是：先带备注调，失败就自动降级成最简参数重试，并在通知里注明「协议端不支持备注/理由」。所以**任何协议端都不会因为多传字段而审批失败**。

群请求同理：`set_group_add_request` 带 `reason` 失败时会自动降级，只做同意/拒绝。

还有一个坑已经处理掉了：**SnowLuma 的群请求 `flag` 不是标准 OneBot 的 `add:<群号>:<uid>`，而是 `slreq:1:<sequence>:<群号>:<eventType>:<filtered>`。** 有些事件不带 `group_id`，插件会从 flag 里把群号抠出来，判定和通知不会因为缺群号而失效。

## 常见问题（群请求）

**打开了「自动同意入群邀请」，被拉群还是没反应？**

1. `/好友 群` 看「入群邀请」是不是「开」，且总开关没关。
2. 看群白名单是否非空 —— 非空时只同意名单里的群，其他群会被跳过（记录里会写「不在群白名单」）。
3. 看 `/好友 记录` 有没有这一条，原因字段会说明是跳过了还是拒绝了。
4. 群邀请事件依赖协议端上报，部分协议端对「某人在群里点邀请机器人」的卡片事件上报不完整，这种情况只能手动同意。

**「自动同意加群申请」打开了却不管用？**

`set_group_add_request` 对加群申请只有机器人**是群主或管理员**才有效，普通成员调用会被 QQ 拒绝。插件日志里会有 `调用 set_group_add_request 失败` 之类的报错。

**会不会把自己拉进乱七八糟的群？**

默认不会 —— 两个开关都是关的。要开就按这个顺序：先只开「入群邀请」→ 观察几天 → 再配群白名单收紧 → 最后才考虑「加群申请」。

## 常见问题（好友申请）

**加了好友没反应？**

1. 用 `/好友` 看「钩子」是不是「已接管 xxx」。显示未挂上就重载插件。
2. 确认 bot 账号的隐私设置是「需要验证」而不是「不允许任何人添加」—— 后者压根不会产生申请事件。
3. 看 `/好友 记录` 里有没有这一条（可能被跳过或拒绝了）。

**收不到通知？**

`admins_id` 里可能混着面板用户名（比如 `astrbot`），那不是 QQ 号。插件只对纯数字的 ID 发私聊。填不准就直接配「通知目标会话」。

**会不会把陌生人全放进来？**

默认会。想收紧，按这个顺序加：黑名单（已知骚扰号）→ 必须填验证语 → 验证语暗号 → 每小时上限调小。白名单适合「都是熟人」的场景。

## 数据与日志

- 状态文件：`AstrBot/data/plugin_data/astrbot_plugin_friend_gate/state.json`（`/好友 路径` 可直接查）
- 插件日志：搜 `[friend_gate]`，能看到每次处理的判定结果与接口返回
