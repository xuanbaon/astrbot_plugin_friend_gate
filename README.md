# 好友门卫（astrbot_plugin_friend_gate）

让 AstrBot 能自己处理 QQ 好友申请：**有人加机器人，秒通过；不欢迎的，直接拒；每一次都告诉你。**

## 它解决什么问题

AstrBot 收到 OneBot 的 `request` 事件后，只把它当成一条空消息丢进消息管道，**不会替你调用 `set_friend_add_request`**。结果就是申请一直躺在 QQ 的「新的朋友」里，等你哪天想起来了手动点。

这个插件直接订阅协议端的好友申请事件，把它变成一个确定的动作：

```
黑名单      → 直接拒绝
白名单      → 直接同意（跳过暗号与频率限制）
必须填验证语 → 没填就拒绝
验证语暗号   → 不含关键词就拒绝
每小时上限   → 超了不拒绝，只留给你人工看（避免误伤）
以上都过    → 自动同意
```

全程**不经过大模型**，不吃 token，也不受模型限流影响。

## 功能

- 自动同意好友申请，可一键暂停（暂停期间申请原样留着，不会丢）
- 黑名单 / 白名单 / 验证语暗号 / 必须填验证语 / 每小时上限
- 同意后自动加备注（模板支持 `{nickname}` `{user_id}` `{comment}`）
- 处理结果私聊通知管理员
- 可选：同意后给对方发一句欢迎语
- 可选：顺便自动同意入群邀请
- 同一个申请只处理一次（跨插件重载也有效）
- 最近 50 条处理记录可查，支持规则试跑

## 安装

在 AstrBot WebUI 的插件页粘贴本仓库地址安装，或：

```bash
cd AstrBot/data/plugins
git clone https://github.com/xuanbaon/astrbot_plugin_friend_gate
```

然后重启核心，或在插件页点「重载」。无第三方依赖。

要求：AstrBot ≥ 4.17.0，平台适配器为 **aiocqhttp**（OneBot v11）。NapCat、Lagrange、SnowLuma 等协议端都走这条链路。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用好友门卫 | 开 | 总开关 |
| 处理结果通知管理员 | 开 | 私聊 `admins_id` 里的 QQ 号 |
| 通知目标会话（可选） | 空 | 填了就直接发到这个会话，优先级更高，形如 `snowluma:FriendMessage:123456` |
| 自动备注 | 空 | 模板，例如 `{nickname}-群友` |
| 同意后发欢迎语 | 空 | 留空不发 |
| 黑名单 QQ | 空 | 一律拒绝 |
| 白名单 QQ | 空 | 直接同意 |
| 验证语暗号 | 空 | 填了就要求验证语含其中一个词 |
| 必须填写验证语 | 关 | 验证语为空就拒绝 |
| 每小时最多自动通过 | 10 | 0 表示不限制 |
| 拒绝时回复的理由 | 空 | 协议端支持时才会带上 |
| 顺便自动同意入群邀请 | 关 | 建议先观察一段时间再开 |

验证语暗号通常不建议开：多数人加好友时验证语是空的，开了会把人全拒掉。想拦陌生人，用白名单 + 黑名单更稳。

## 命令

仅管理员可用：

```
/好友                      运行状态与累计统计
/好友 关                    暂停自动处理（申请先留着）
/好友 开                    恢复自动处理
/好友 记录                  最近处理过的申请
/好友 路径                  打印状态文件位置
/好友 测试 <QQ> [验证语]     只试跑判定规则，不会真的同意
```

## 兼容性说明

不同协议端对 `set_friend_add_request` 的参数支持不一样。有的一多传 `remark`（备注）或 `reason`（拒绝理由）就报参数错误 —— SnowLuma 就只认 `flag` + `approve`。

插件的处理方式是：先带备注调，失败就自动降级成最简参数重试，并在通知里注明「协议端不支持备注/理由」。所以**任何协议端都不会因为多传字段而审批失败**。

## 常见问题

**加了好友没反应？**

1. 用 `/好友` 看「钩子」是不是「已接管 xxx」。显示未挂上就重载插件。
2. 确认 bot 账号的隐私设置是「需要验证」而不是「不允许任何人添加」—— 后者压根不会产生申请事件。
3. 看 `/好友 记录` 里有没有这一条（可能被跳过或拒绝了）。

**收不到通知？**

`admins_id` 里可能混着面板用户名（比如 `astrbot`），那不是 QQ 号。插件只对纯数字的 ID 发私聊。填不准就直接配「通知目标会话」。

**会不会把陌生人全放进来？**

默认会。想收紧，按这个顺序加：黑名单（已知骚扰号）→ 必须填验证语 → 验证语暗号 → 每小时上限调小。白名单适合「都是熟人」的场景。

## 数据与日志

- 状态文件：`AstrBot/data/plugin_data/astrbot_plugin_friend_gate/state.json`（`/好友 路径` 可直接查）
- 插件日志：搜 `[friend_gate]`，能看到每次处理的判定结果与接口返回
